# ecagent
Agentic AI assistant for discovering and planning extracurricular activities

## Repo Structure

```
ecagent/
├── agent/                          # Agent implementation (see docs/agent.md)
│   ├── agent.py                    # Main agent: router (supervisor loop), calls subagents, checks replies
│   ├── memory.py                   # Structured notes (state, summary, plan), context management, save/restore
│   ├── compactor.py                # Resolve contradictions in memory, summarize near the token limit
│   ├── retriever.py                # Find + score events/clubs (DB keyword search, web fallback)
│   ├── recommender.py              # Rank activities (soft preferences) and candidate plans (pairwise judge)
│   ├── scheduler.py                # Generate + check candidate plans, verified calendar adds/removes
│   ├── calendars.py                # Calendar tools: SimulatedCalendar (eval), GoogleCalendar (real use)
│   ├── gmail.py                    # Gmail: activities + commitments from emails (read only)
│   ├── registration.py             # Registration tools: SimulatedRegistration (eval), ManualRegistration
│   ├── google_auth.py              # Google OAuth token refresh (requests only)
│   └── model_log.json              # Action log, one JSON object per line (generated)
│
├── docs/                           # Project documentation
│   ├── agent.md                    # Agent design, experimental setup, references
│   ├── design-decisions.md         # Design decisions (benchmark, eval, agent components)

│   └── evaluation.md

├── eval/                           # Benchmark and evaluation

├── scraper/                        # Campus event + RSO scraping
```

## Setup

```bash
pip install -r requirements.txt
export ANTHROPIC_API_KEY=...        # all modules use claude-sonnet-4-6 (MODEL in utils.py)
                                    # Windows PowerShell: $env:ANTHROPIC_API_KEY="..."
python -m scraper.scrape            # build data/campus.db (or copy the eval snapshot into data/)
```

Run everything from the repo root (imports are `agent.*`, `scraper.*`, `utils`).

### Google Calendar + Gmail (real use)

Secrets stay **outside the repo**, in the folder that contains it (`../client_secret.json`,
`../google-token.json`; override with `ECAGENT_SECRETS_DIR`).

1. [Google Cloud console](https://console.cloud.google.com), signed in as the test account: create a project.
2. **APIs & Services → Library**: enable **Google Calendar API** and **Gmail API**.
3. **Google Auth Platform** (OAuth consent screen): Branding (app name, support email); Audience: External,
   add the test account under **Test users**.
4. **Clients → Create client → Desktop app**, download the JSON, save it as `../client_secret.json`.
5. Log in once (opens the browser), then run the live test:

```bash
python -m scripts.google_login      # rerun when it expires: every 7 days while the app is in Testing mode
python -m scripts.live_test         # calendar: add/read back/remove a test event; gmail: read + extract
python -m scripts.live_test --agent --interests photography   # then chat with the whole agent
```

The agent reads the primary calendar (busy time) and adds approved activities to a separate **ECAgent**
calendar. Gmail is read only: announcement emails become activities to recommend, the student's own
commitments (exams, interviews) become busy time. Scopes: `calendar`, `gmail.readonly`.

## Usage

```python
from agent.agent import ECAgent

agent = ECAgent(memory_path="memory.json")          # memory saved after each turn
reply, selection = agent.run("Can you find me an activity that works with my schedule?")

# real accounts (after the Google setup above)
from agent.calendars import GoogleCalendar
from agent.gmail import EmailSource, GmailInbox
agent = ECAgent(calendar=GoogleCalendar(), inbox=EmailSource(GmailInbox()))
```

`run` returns the reply and the activities shown or added this turn. Plans are only added to the calendar
after the student approves them in the next message: a separate yes/no check (`check_approval`) runs first,
and `register` / `calendar` are only offered to the router (and only executed) when it says yes. Every add
and remove is verified by reading the calendar back; a failed add is retried once, without duplicates.

Eval uses `SimulatedCalendar(events=..., fail_on=...)` and `SimulatedRegistration(fail_on=...)`
(e.g. `fail_on={1}` for task 9's tool error), `inbox=None` and `use_web=False`.
